Connect an AI assistant to your glades

Meadow runs an MCP server, so an assistant you already use can read a glade as shapes and arrows, draw diagrams on it and tidy them up. It edits live, like one more person on the glade, and it can never reach more than you allow.

Two ways in

Sign in, or paste a token

Both end in the same place: a token that acts as you, narrowed to what you chose. The server address is https://meadow.creara.in/mcp, or your own address followed by /mcp if you run Meadow yourself.

Sign in (OAuth)

For assistants that connect from a web page. Add the server address, and the assistant sends you to Meadow. Sign in, tick the glades it may open and what it may do on each, and choose Allow. Nothing to copy, and nothing to paste.

  • Starts with no glades picked, so it gets only what you tick
  • Its access renews by itself; a connection unused for thirty days has to sign in again
  • The consent screen shows whether Meadow could verify who is asking

An access token

For coding agents, editors and scripts. In Meadow, open Profile, Assistants and tokens, press New token, name it after what will use it, and create it. It starts with mdw_ and is shown once, so copy it straight into the assistant's settings.

  • Classic or fine-grained, explained below
  • Expires after 30 days, 90 days, a year, or never
  • Sent as Authorization: Bearer mdw_...

Tokens

Classic and fine-grained tokens

A classic token is everything your account can do, on every glade you can open, including making and importing glades. Use it for your own agent on your own machine. A fine-grained token opens only the glades you pick, each with its own permissions, and is what signing in gives an assistant.

PermissionFine-grained tokenClassic token
ViewReading a glade you picked. Always on for a picked gladeEvery glade you can open
EditAdding, changing, moving, relabelling and connecting objects, per gladeWherever you can edit
DeleteRemoving objects, per gladeWherever you can edit
Create gladesOff unless turned on. A glade it makes joins its own list with view, edit and deleteAlways

For example, with glades A to E you might pick A, C and D: view and edit on A, view only on D, view and delete on C. B and E do not exist for that token. A token with Create glades on and no glades at all can only ever touch what it made itself.

Whatever the kind, a token never does more than you can: if you are a viewer on a glade, or its owner has locked it, the token cannot edit it either, and a glade with a password cannot be opened with a token. The server enforces this on every change, not the assistant. Change a token's permissions or revoke it under Profile, Assistants and tokens, and anything using it picks that up straight away, including a glade it has open.

Setup

Connect your assistant

Web assistants sign in. Coding agents and editors take the server address with a token, or run the server on your machine.

ChatGPT Claude Claude Code VS Code Codex Cursor and others

ChatGPT

Signs in with OAuth

  1. Open ChatGPT's settings, go to Connectors and create one.
  2. Name it Meadow. Under Connection choose Server URL and enter https://meadow.creara.in/mcp.
  3. Set Authentication to OAuth, confirm the notice about custom servers, and choose Create.
  4. Choose Sign in with Meadow, sign in, pick the glades and permissions, and choose Allow.

Claude, on the web and desktop

Signs in with OAuth, or takes a token

  1. Open Settings, Connectors and choose Add custom connector.
  2. Enter https://meadow.creara.in/mcp.
  3. Leave Authentication on Sign in now and OAuth client on Use Claude's published identity. Register automatically works too.
  4. Add it, choose Connect, sign in to Meadow, pick the glades and permissions, and choose Allow.

Or with a token

Choose No sign-in, and under Request headers add authorization with your token as the value, written as Bearer mdw_...

Claude Code

A token in a header

claude mcp add --transport http meadow https://meadow.creara.in/mcp \
  --header "Authorization: Bearer mdw_..."

VS Code

Copilot agent mode, a token asked for once

Add this to .vscode/mcp.json. VS Code asks for the token the first time and keeps it out of the file.

{
  "inputs": [
    { "id": "meadow-token", "type": "promptString", "description": "Meadow access token", "password": true }
  ],
  "servers": {
    "meadow": {
      "type": "http",
      "url": "https://meadow.creara.in/mcp",
      "headers": { "Authorization": "Bearer ${input:meadow-token}" }
    }
  }
}

Codex

The server on your machine, with a token

Build the server once from the source (pnpm install, then pnpm --filter @meadow/mcp build), then add:

[mcp_servers.meadow]
command = "node"
args = ["/path/to/meadow-mcp.js"]
env = { MEADOW_API_URL = "https://meadow.creara.in", MEADOW_TOKEN = "mdw_..." }

Cursor, Antigravity and other JSON configs

The server on your machine, with a token

With the server built as for Codex, add it to the client's MCP settings file:

{
  "mcpServers": {
    "meadow": {
      "command": "node",
      "args": ["/path/to/meadow-mcp.js"],
      "env": { "MEADOW_API_URL": "https://meadow.creara.in", "MEADOW_TOKEN": "mdw_..." }
    }
  }
}

A client that cannot show pictures in tool results can turn off the snapshots attached to writes with MEADOW_MCP_SNAPSHOTS=off. The full reference, including running the HTTP server yourself, is the MCP guide (opens in a new tab).

Once connected

What an assistant can do

Tools a token cannot use on any glade are not offered at all, and a refusal names the permission that is missing.

Read

List the glades it can open, read one as nodes and arrows with what each arrow connects, search by label, export a glade as a .meadow.json file or a Mermaid flowchart, and take a picture of it. View access is enough.

Draw

Add shapes, sticky notes and text, connect them, relabel and move them, or draw a whole diagram from a list of nodes and edges or from Mermaid. Leave out positions and Meadow lays the diagram out and routes its arrows.

Check its work

Every write comes back with a picture and a list of layout problems: text that overflows, lines through shapes, labels on labels. It can tidy a messy diagram in one call, and preview any change before making it.

In control

What you can count on

You see who is asking

When an assistant identifies itself with an address it controls, the consent screen says Verified with that address. When it registered itself instead, the screen says Meadow cannot confirm who it is, since a name can be anything. Check that line before allowing an assistant that claims a familiar name.

Its edits are visible

The assistant joins the glade among the people there, named after itself, and its edits arrive live. Your undo tracks only your own changes, so to take back an assistant's edit, ask it to, or delete what it made.

Revoking is immediate

Revoke a token or a signed-in connection under Profile, Assistants and tokens and it stops at once, including on a glade it has open. Signed-in connections renew their access every hour, and if an old renewal is ever used twice, Meadow treats it as stolen and ends the connection.
